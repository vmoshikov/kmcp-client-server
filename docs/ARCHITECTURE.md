# Архитектура KAgent Operator

## Обзор

KAgent Operator - это Go HTTP сервис, который выступает в качестве прокси между пользователями и MCP Server, запускающим tools для анализа Kubernetes кластеров.

## Компоненты системы

### 1. HTTP API Сервис (main.go)

**Ответственность:**
- Прием HTTP запросов от пользователей
- Валидация входных данных
- Оркестрация вызовов MCP Server
- Формирование ответов

**Эндпоинты:**
- `POST /analyze` - основной эндпоинт для анализа кластера
- `GET /health` - проверка здоровья сервиса

**Структура запроса:**
```go
type AnalyzeRequest struct {
    ClusterID  string                 // Идентификатор кластера
    ToolNames  []string               // Список tools для выполнения
    Parameters map[string]interface{} // Параметры для tools
}
```

**Структура ответа:**
```go
type AnalyzeResponse struct {
    ClusterID   string                 // Идентификатор кластера
    ToolResults map[string]interface{} // Результаты выполнения tools
    Error       string                 // Ошибка (если есть)
}
```

### 2. MCP Client (mcp/client.go)

**Ответственность:**
- Установка соединения с MCP Server
- Формирование запросов в формате MCP Protocol
- Отправка HTTP запросов к MCP Server
- Обработка ответов и ошибок

**Ключевые методы:**
- `NewMCPClient(baseURL)` - создание нового клиента
- `CallTools(ctx, toolNames, parameters)` - вызов нескольких tools
- `callTool(ctx, toolName, parameters)` - вызов одного tool

**Формат MCP запроса:**
```json
{
  "method": "tools/call",
  "params": {
    "name": "kubectl_get_pods",
    "arguments": {
      "namespace": "default"
    }
  }
}
```

**Формат MCP ответа:**
```json
{
  "result": {
    "pods": [...],
    "count": 5
  },
  "error": null
}
```

## Поток выполнения запроса

### Шаг 1: Получение HTTP запроса

```
Пользователь → POST /analyze → HTTP Handler
```

1. HTTP сервер получает POST запрос на `/analyze`
2. Декодируется JSON тело запроса в структуру `AnalyzeRequest`
3. Выполняется валидация:
   - Проверка наличия `toolNames`
   - Проверка формата данных

### Шаг 2: Формирование запросов к MCP Server

```
HTTP Handler → MCP Client → Формирование MCP запросов
```

1. Для каждого tool из `toolNames` создается отдельный MCP запрос
2. Параметры из `parameters` передаются в каждый tool
3. Формируется структура `MCPRequest` с методом `tools/call`

### Шаг 3: Вызов MCP Server

```
MCP Client → HTTP POST → MCP Server
```

1. MCP Client отправляет HTTP POST запрос к MCP Server
2. Запрос содержит JSON в формате MCP Protocol
3. Используется контекст для управления таймаутами

### Шаг 4: Выполнение tools на MCP Server

```
MCP Server → Tool Execution → Kubernetes Cluster
```

1. MCP Server получает запрос и определяет, какой tool нужно выполнить
2. Tool выполняется с переданными параметрами
3. Tool взаимодействует с Kubernetes кластером через:
   - kubectl команды
   - Kubernetes API
   - Другие инструменты (helm, istioctl, etc.)

### Шаг 5: Получение результатов

```
MCP Server → HTTP Response → MCP Client
```

1. MCP Server собирает результаты выполнения tool
2. Формируется ответ в формате MCP Protocol
3. HTTP ответ отправляется обратно к MCP Client

### Шаг 6: Обработка результатов

```
MCP Client → Результаты → HTTP Handler
```

1. MCP Client получает ответ от MCP Server
2. Проверяется наличие ошибок
3. Результаты парсятся из JSON
4. Результаты всех tools собираются в единую структуру

### Шаг 7: Формирование ответа пользователю

```
HTTP Handler → JSON Response → Пользователь
```

1. Формируется структура `AnalyzeResponse`
2. Результаты всех tools включаются в `ToolResults`
3. JSON ответ отправляется пользователю

## Обработка ошибок

### Уровень HTTP Handler

**Ошибки валидации (400 Bad Request):**
- Неверный формат JSON
- Отсутствие обязательных полей
- Пустой список `toolNames`

**Ошибки выполнения (500 Internal Server Error):**
- Ошибки подключения к MCP Server
- Таймауты запросов
- Ошибки парсинга ответов

### Уровень MCP Client

**Ошибки подключения:**
- Недоступность MCP Server
- Сетевые ошибки
- Таймауты

**Ошибки MCP Server:**
- Ошибки выполнения tool
- Неверный формат ответа
- Ошибки парсинга

**Стратегия обработки:**
- Если один tool завершился с ошибкой, остальные tools продолжают выполняться
- Ошибка для конкретного tool включается в результаты как `{"error": "..."}`
- Критические ошибки (недоступность MCP Server) приводят к ошибке всего запроса

## Конфигурация

### Переменные окружения

- `PORT` - порт HTTP сервера (по умолчанию: 8080)
- `MCP_SERVER_URL` - URL MCP Server (по умолчанию: http://localhost:3000/mcp)

### Таймауты

- HTTP запросы к MCP Server: 30 секунд
- Можно настроить через изменение `httpClient.Timeout` в `MCPClient`

## Масштабирование

### Горизонтальное масштабирование

Сервис stateless, можно запускать несколько реплик:
- Использовать Kubernetes Deployment с несколькими replicas
- Использовать LoadBalancer или Ingress для распределения нагрузки

### Вертикальное масштабирование

- Увеличить ресурсы контейнера (CPU, Memory)
- Настроить таймауты для длительных операций

## Безопасность

### Текущая реализация

- Валидация входных данных
- Ограничение размера тела запроса (через HTTP сервер)
- Таймауты для предотвращения зависаний

### Рекомендации для production

- Аутентификация (JWT, API keys)
- Авторизация (RBAC)
- Rate limiting
- TLS/HTTPS
- Валидация и санитизация всех входных данных
- Логирование и мониторинг

## Мониторинг

### Метрики для отслеживания

- Количество запросов
- Время выполнения запросов
- Количество ошибок
- Доступность MCP Server
- Использование ресурсов

### Логирование

- Все HTTP запросы
- Ошибки выполнения
- Время выполнения операций
- Статус подключения к MCP Server

## Будущие улучшения

1. **Параллельное выполнение tools**
   - Использовать goroutines для параллельного вызова tools
   - Улучшить производительность при множественных tools

2. **Кэширование результатов**
   - Кэшировать результаты анализа для часто запрашиваемых данных
   - Настраиваемое TTL для кэша

3. **Поддержка SSE транспорта**
   - Реализовать поддержку Server-Sent Events для real-time обновлений
   - Потоковая передача результатов

4. **WebSocket поддержка**
   - Real-time обновления состояния анализа
   - Двусторонняя связь с клиентом

5. **Расширенная обработка ошибок**
   - Retry механизм для временных ошибок
   - Circuit breaker для защиты от недоступности MCP Server
